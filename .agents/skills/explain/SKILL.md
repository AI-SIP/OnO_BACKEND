# explain — 코드 흐름과 원리 설명

**읽기 전용: 코드 수정과 커밋을 하지 않는다.**

## 대상

$ARGUMENTS

> Claude Code 는 위 자리에 슬래시 명령 인자를 넣는다. 비어 있거나 `$ARGUMENTS` 가 그대로 보이면 사용자 메시지에서 대상을 읽는다.

## 단계

1. **호출 경로 추적**: 추측하지 말고 진입점부터 `Controller → Service → Repository → 쿼리` 순서로 따라간다. 데이터 흐름, 변환 지점, 분기 조건을 확인한다.
   - Claude Code 에서는 `.claude/agents/code-tracer` 에 맡긴다. 서브에이전트가 없는 환경에서는 직접 추적한다.
2. **흐름 설명**
   - 요청이 처리되는 순서 (`요청 진입점 → 핵심 로직 → DB/외부 연동 → 응답`)
   - 왜 이렇게 설계했는가 (도메인 이유, 성능 이유, 제약 조건)
   - 주요 클래스와 메서드의 역할 (`파일:라인`)
   - API 계약, validation, 예외 처리, 트랜잭션, 권한 검증 지점
3. **다이어그램 (선택)**: 흐름이 복잡하면 텍스트 시퀀스 다이어그램을 붙인다.

개선 제안은 실제 리스크가 있을 때만, 근거와 함께 짧게 덧붙인다.
