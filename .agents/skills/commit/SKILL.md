# commit — 커밋 생성

**변경 범위를 확인한 뒤 논리 단위별로 `git add` 와 `git commit` 까지 수행한다.** push 는 하지 않는다(`pr` 단계에서 한다).

## 맥락

$ARGUMENTS

> Claude Code 는 위 자리에 슬래시 명령 인자를 넣는다. 비어 있거나 `$ARGUMENTS` 가 그대로 보이면 사용자 메시지를 맥락으로 쓴다.

## 단계

1. `git status` 와 `git diff HEAD` 로 현재 변경 전체를 파악한다.
2. 사용자 변경과 이번 작업 변경을 구분한다. 임의로 되돌리지 않는다.
3. 변경을 논리 단위로 나눈다. 각 단위는 단일 목적이고 독립적으로 빌드 가능해야 하며, 관련 없는 변경을 섞지 않는다.
4. 단위마다 아래 형식으로 메시지를 정한다. 이슈 번호가 있으면 요약 끝에 `(#번호)` 를 붙인다.
5. 단위마다 필요한 파일만 `git add` 하고 `git commit` 한다. 여러 줄 메시지는 `git commit -F <파일>` 이나 heredoc 으로 넘긴다.
6. 커밋 후 `git status` 로 남은 변경이 있는지 확인한다.

## 메시지 형식

```text
[Feat] 한 줄 요약 (#이슈)
- 상세 1
- 상세 2
```

- 태그: `[Feat]` / `[Fix]` / `[Refactor]` / `[Chore]` / `[Test]` / `[Docs]` / `[Perf]`
- 요약과 상세는 한국어로, 무엇을 왜 바꿨는지가 드러나게 쓴다.

## 산출물

- 커밋 해시, 메시지, 포함 파일
- 작업 트리에 남은 변경 여부
