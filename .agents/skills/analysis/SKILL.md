# analysis — 원인 규명

**읽기 전용: 코드 수정과 커밋을 하지 않는다.**

## 입력

$ARGUMENTS

> Claude Code 는 위 자리에 슬래시 명령 인자를 넣는다. 비어 있거나 `$ARGUMENTS` 가 그대로 보이면 사용자 메시지에서 대상을 읽는다.

- 대상이 없으면 `git status`, `git diff HEAD` 의 현재 변경분을 분석 대상으로 삼는다.
- 그래도 대상이 좁혀지지 않으면 먼저 짧게 묻는다: 무슨 증상인가, 원하는 결과는 무엇인가, 관련 파일이나 로그가 있는가.

## 단계

1. **가설 분해**: 증상을 설명할 수 있는 가설을 3~5개 나열한다.
2. **조사**: 관련 코드 흐름, 설정, 로그, `git log/diff/show` 를 읽기 전용으로 확인한다.
   - Claude Code 에서는 `.claude/agents/` 의 `code-tracer` 를 기본으로 쓰고, 가설에 따라 `permission-auditor`, `perf-reviewer`, `logic-reviewer`, `db-safety` 를 병렬로 붙인다.
   - 서브에이전트가 없는 환경(Codex 등)에서는 같은 관점을 직접 순서대로 확인한다.
3. **근거 대조**: 각 가설을 `파일:라인` 근거로 지지하거나 반박한다. 추정은 근거로 쓰지 않는다.
4. **반증**: 상위 레이어에서 이미 막히는지, 실제로 호출 가능한 경로인지, 다른 설정이 우선하는지 확인한다.
5. **자가 반증 질문**에 답하고 필요하면 결론을 고친다.
   - 내가 놓쳤을 가능성이 큰 것은?
   - 이 결론이 틀렸다면 어떤 조건 때문인가?

## 산출물 (텍스트, 저장하지 않음)

- 한 문장 요약
- 근거 목록 (`파일:라인`)
- 근본 원인과 확신도 (높음/중간/낮음)
- 자가 반증 결과
- 다음 단계 제안 (`plan` 또는 추가 조사)
