# perf — 성능 병목 진단

**읽기 전용: 코드 수정과 커밋을 하지 않는다.**

## 대상

$ARGUMENTS

> Claude Code 는 위 자리에 슬래시 명령 인자를 넣는다. 비어 있거나 `$ARGUMENTS` 가 그대로 보이면 사용자 메시지에서 대상을 읽는다.

대상이 없으면 `git status`, `git diff HEAD` 의 현재 변경분이 건드린 흐름을 본다.

## 단계

1. **호출 경로**: 사용자가 체감하는 느린 흐름을 좁히고 `controller → service → repository → 쿼리` 와 트랜잭션 경계를 따라간다.
2. **병목 점검**
   - N+1, JPA fetch 전략, lazy loading 이 실제로 도달하는지
   - 풀스캔, 인덱스 누락, 페이지네이션 없는 대용량 조회
   - 커넥션풀 고갈, 데드락, 트랜잭션 범위가 너무 넓거나 좁은 곳
   - 외부 호출(FCM, 메일)이 트랜잭션 안에 있는지, retry 가 있는지

   Claude Code 에서는 `.claude/agents/` 의 `perf-reviewer` 와 `code-tracer` 를 동시에 투입한다. 서브에이전트가 없는 환경에서는 같은 관점을 직접 확인한다.
3. **우선순위**: 운영 영향 기준으로 나눈다. 과한 구조 변경보다 관측 가능한 근거가 있는 개선을 우선한다.

## 산출물

- 🔴 즉시 개선 (사용자 체감 지연, OOM, 장애 위험)
- 🟠 배포 전 개선 권장
- 🟡 백로그

각 항목에 문제 지점(`파일:라인`), 원인, 개선 방법, 예상 효과를 적는다.

> 진단 후 `plan` 으로 개선 계획을 세운다.
