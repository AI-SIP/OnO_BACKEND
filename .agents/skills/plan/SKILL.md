# plan — 구현 계획서

**코드 수정과 커밋을 하지 않는다. 계획서 파일만 저장한다.**

## 작업

$ARGUMENTS

> Claude Code 는 위 자리에 슬래시 명령 인자를 넣는다. 비어 있거나 `$ARGUMENTS` 가 그대로 보이면 사용자 메시지에서 작업을 읽는다.

인자가 없으면 `git status`, `git diff HEAD` 의 현재 변경분을 보고 후속 구현이나 정리 계획을 쓴다.

## 단계

1. **조사**: 관련 코드 흐름, API 계약, DB 스키마, 인증과 권한, 기존 문서를 확인한다. 근거는 `파일:라인`.
   - Claude Code 에서는 `code-tracer` 를 기본으로 쓰고 필요하면 `permission-auditor`, `perf-reviewer`, `db-safety` 를 붙인다.
   - DB 스키마 변경이 있으면 `migration-safety`, DTO 나 엔드포인트 변경이 있으면 `api-contract-checker` 로 미리 검토한다.
   - 서브에이전트가 없는 환경에서는 같은 관점을 직접 확인한다.
2. **계획서 작성**: 아래 절을 넣는다.
   - 목적과 사용자 시나리오 (한 줄 요약 포함)
   - 구현 범위와 제외 범위, 영향 받는 파일과 레이어
   - 구현 단계 (번호, 단계마다 독립적으로 구현 가능하게)
   - 위험 요소 (FCM 발송, 데이터 마이그레이션, 권한 변경, API 호환성)
   - 테스트 방향 (사용자 격리와 권한 실패 포함)
   - 커밋 분할 제안
   - 확인이 필요한 질문 (불확실한 API 계약이나 null 가능성은 추측하지 않고 질문으로 남긴다)
3. **저장**: `docs/plans/<작업명>_plan.md` 에 저장하고 경로를 알린다. `docs/` 는 gitignore 대상이라 로컬에만 남는다.
4. **승인 대기**: "계획서를 검토해주세요. 승인하면 feat 으로 진행합니다." 라고 안내한다.

> 🔴 계획서 검토가 가장 중요한 체크포인트다. 승인 전에는 구현하지 않는다.
